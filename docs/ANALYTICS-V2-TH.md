## ขอบเขตความหมาย
1. ไม่แสดงชื่อ Facebook/Google ของคนที่กดเข้าเว็บ และไม่เชื่อม session เข้าชื่อ Lead อัตโนมัติในรอบนี้ form_success เป็น browser event ส่วนยอด Lead จริงอยู่เมนู Lead เดิม
2. Country/region/city อ่านจาก request.cf ฝั่ง Cloudflare ผ่าน request context ไม่รับค่าพื้นที่จาก client ไม่เก็บ IP ดิบ พิกัด GPS หรือละติจูด/ลองจิจูด ถ้าไม่มีข้อมูลให้แสดงไม่ทราบ ไม่ตีความว่าเป็นที่อยู่จริงของผู้เข้าชม
3. VPN เครือข่ายมือถือและข้อมูลเครือข่ายทำให้พื้นที่คลาดเคลื่อนได้ Preview อาจไม่มี request.cf ต้องตรวจบนโดเมนจริงหลัง Deploy
4. ต้องอนุญาต analytics รุ่นใหม่ก่อนเก็บข้อมูล อัปเดต key ความยินยอมเป็น v2 จึงขออนุญาตใหม่จากผู้ใช้เดิม เปิด Do Not Track จะไม่เก็บ; ไม่บันทึกข้อความในฟอร์ม และเพิ่มคำอธิบาย Analytics ในหน้า privacy 3 ภาษา
5. เก็บอีเวนต์ไม่เกินช่วงรายงาน 90 วัน การลบแถวเก่าจริงทำเมื่อมี event ใหม่ ไม่มี cron เพิ่มในงานนี้
6. ไม่มี heatmap, session replay, รายได้, CPL/ROAS, การนำเข้าต้นทุนโฆษณา หรือผลปิดการขายในรายงาน Analytics นี้
7. หนึ่งเซสชันอาจถูกนับในหลายหน้าหรือหลายชั่วโมง อย่าบวกทุกแถวเพื่อหาจำนวนคนทั้งหมด
8. การเทียบช่วงก่อนหน้าอาจมีข้อมูลไม่เต็มเมื่อเพิ่งติดตั้งหรือเมื่อเก่ากว่า retention ไม่ควรสรุปว่าแคมเปญโต/ตกจากข้อมูลน้อย
9. สถิติมาจาก browser และความยินยอม ไม่ใช่ผู้เข้าชมทุกคน ข้อมูลอาจตกหล่นเมื่อปิดหน้า/ตัดเน็ต และ event จาก client ไม่ใช่หลักฐานธุรกรรม ไม่มีการเติมตัวเลขจำลอง

## ตรวจหลัง Deploy
- เปิดเว็บลูกค้าใหม่ อนุญาตสถิติ v2 (หลังบ้าน/cms-preview ไม่นับ)
- ดู Network: POST /api/analytics/events ควรได้ 200; 400=payload/เวอร์ชัน, 403=origin, 429=จำกัดการส่ง, 503=DB/schema/service
- เปิดโครงการ กดสอบถาม เริ่มกรอกแล้วส่ง TEST ที่ระบุชัดเจนว่าเป็นข้อมูลทดสอบ กลับหลังบ้านกดโหลดใหม่
- ตรวจไทม์ไลน์/ประเทศ/แคมเปญตรงกับการทดสอบ และตรวจแถวใน D1 analytics_events_v2 + enquiries ด้วยตัวเองก่อนใช้รายงานกับลูกค้าจริง
- ถ้ายัง 0 ให้ตรวจ consent, Do Not Track, ad blocker, ตัวกรองช่วงเวลา, ผล Deploy และ DB binding; 0 ไม่พิสูจน์ว่าไม่มีคนเข้า
- ไม่ต้องเชื่อม API ภายนอกสำหรับประเทศ ไม่มีการเปลี่ยน Cloudflare bindings ในชุดนี้
